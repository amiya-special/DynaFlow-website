INTRODUCTION

Collaboration should fit the task.

Different tasks need different collaboration: some are best answered directly, others need parallel exploration or ordered reasoning and verification. DynaFlow lets the Main Agent design its own collaboration, deciding when a workflow is worth it and writing a task-specific program that defines roles, dependencies, information exchange, and checks.

METHOD

A workflow is an action.

The Main Agent writes, runs, and revises a program for each collaboration.

01

Choose & synthesize

Answer directly, call a tool, or write a JavaScript workflow.

02

Execute & exchange

Run sub-agents in sequence or in parallel and pass outputs to the agents that need them.

03

Observe & adapt

Read the outputs and trace, then answer or launch a follow-up workflow.

04

Train the orchestrator

Two-stage SFT trains only the Main Agent; sub-agents stay frozen.

WORKFLOW ANALYSIS

How the programs use information.

First workflows under Forced execution, before and after training.

Structure and information use

Hybrid parallel-and-sequential programs rise from 3.4% to 85.6%, and 97.7% use upstream outputs explicitly.

Workflow design quality

Stage 2 curation halves major information-flow defects (1.9% → 0.9%) while using fewer sub-agents.

Roles adapt to the task

Solvers and verifiers dominate math; researchers make up 59.6% of HotpotQA sub-agents.
